## Visual grammar

- Build an **instrument with a purpose**: a dark screen sits in a substantial warm-plastic or painted-metal frame. Around it, a small set of physical controls and status lights indicates what the viewer is doing. The reference introduces this at the opening and demonstrates toggles/knobs at about 01:45–02:05.
- Screen content uses a restrained phosphor green or amber, aligned monospaced text, simple line drawings, and modular technical readouts. At about 01:25–01:45 the video isolates the screen texture and character spacing; at 02:10–02:25 it uses structured telemetry.
- Make technical state visible. A button press causes a meaningful change, a lamp represents completion, a connector shows a dependency, and a typed line introduces the next fact. Decorative readings should never masquerade as measured facts.
- Keep two scales: the whole console explains the system; a close view of one screen or control teaches a detail. The closing overview treats earlier scenes as modules in a larger cockpit.
- The visual attraction is tangible, repairable equipment with understandable controls. The episode contrasts this with smooth glass at roughly 03:10–03:22, then distinguishes it from neon-city, vaporwave, and translucent Y2K looks.

## Motion and practical recipes

The direct frames show short typed additions, a temporary television-noise interruption, zooming toward controls, sequential lamp changes, and rotating knob indicators. Use this vocabulary with original staging:

1. **Boot into a lesson.** Show one short task-relevant status line, add a second, then expand the working screen into the main diagram. Keep the introduction about the actual topic; avoid a long fake boot log.
2. **Control → consequence.** An on-screen toggle changes position over roughly 0.15–0.25 seconds; a lamp switches once; the diagram updates over 0.5–0.9 seconds. Explain an agent enabling a skill or choosing a preset through this linked action.
3. **Wiring reveal.** Draw one connection at a time between a central skill module and agent panels. Preserve the same canonical source label while each panel receives its own alias. Use a pointer shape rather than visually cloning the source file.
4. **Console traversal.** Move between adjacent panels over 0.6–1.0 seconds. Keep a shared bezel edge or device label visible long enough to show that the lesson is moving through one system. Hold still for important reading.
5. **Readout construction.** Reveal concise labels or lines, then a diagram. Type only enough text to establish the terminal behavior; long narration should not be displayed character by character.

Optional brief signal interference can mark a chapter change; it should not repeatedly interrupt explanations. Use a measured procedural rhythm with intermittent activity, rather than constant flashing or constant camera drift. These timing values are proposed settings and require a sample render.

## Avoid and accept

Avoid equating this preset with a generic green text overlay, endless code rain, purple/cyan cyberpunk streets, holographic glass panels, or RGB decoration. A convincing segment needs a material object, readable information, and a visible relation between action and result.

Acceptance: the viewer can identify the current system state and why it changed; captions and exact paths remain readable at phone size; at least one major concept is taught by a control/diagram transformation; the episode retains the topic and production specifications supplied to the main skill.
