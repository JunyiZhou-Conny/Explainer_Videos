## 为什么要中英混用

- 中国的 MLOps 工程师和助教带实验课时本来就中英混着说：“push 到 main”“开一个 PR”“这个 job 红了”“整个 run 挂了”“每个 job 都是一台全新的 runner”“把 image 当 artifact 传过去”“docker load 一下”“加一个 secret”“配一个 webhook”“commit 被 hook 拦了”“CI 挂了”。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A4）。
- 这是跟练视频：观众要照着敲命令，要在英文 README、终端、job 日志、步骤列表和 GitHub 页面里找东西。命令、参数、文件名和路径、分支名、image 名、`ci.yml` 里的 job 名和步骤名、GitHub 页面上的按钮和选项、README 的小节名、日志里的原文一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 GitHub 中文文档和中文 CI / Git 文献里的标准译名，方便搜索：工作流、事件、触发条件、步骤、依赖、并行、条件执行、分支、合并、分支保护、状态检查、持续集成、持续部署、静态分析、编码规范、退出码、暂存、工作区。
- 双语字幕带把英文原句放在每行中文的正下方，所以中文行不加任何括注，也不给保留英文的词加中文解释。
- 这个系列不翻译画面：终端、job 日志面板、步骤列表、run 的依赖图、act 的输出、代码面板、README 卡片、GitHub 页面示意图、Slack 卡片、标签、进度条、pipeline 条、课件标签和思考题卡片都保持英文，只翻译旁白。

## 总原则

用一位中国 MLOps 助教在实验课上带同学一步步操作时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。

1. **实物原样**：观众要输入、要在屏幕上对照的东西（命令、参数、文件名和目录名、路径、分支名、image 名、YAML 键、`ci.yml` 里的 job 名和步骤名、工作流名 CI Pipeline、commit 信息、GitHub 页面上的标签和按钮、README 小节名、旁白引用的日志和报错原文）逐字照抄，不翻译、不变形、不加引号。检查器逼出来的例外（实物里有下划线、= < > + $ 或括号）按旁白的说法写（A6），英文行显示原样（D4）。画面上的一切都是英文，只翻译旁白。
2. **实验课口语里的英文，封闭清单**：系列已有的 repo、clone、commit、push、fork、origin、container、image、tag、Dockerfile、port、localhost、pipeline、hook、lint、linter、shell、root、bug、pin、ID、CI、API、JSON、YAML、URL；**这一讲新增 job、runner、artifact、action、run（一次工作流运行）、secret、webhook、PR、CD**。
3. **其余用中文标准术语**（A3、A7–A10、A13–A15）。
4. **视频里的图按意思译，一个图一个词**：门禁（读退出码的步骤，以及课上说的、能拒绝的那道门）、铃（Actions 在 push 之后才报告）、行李箱（V5 里装 image 的箱子）、旁路（continue-on-error 把失败引到一边）、证人（act，第二个证人）、循环（课件第 21 页的 CI 循环）、链（V1 的 hook 链）、开头那个谜题（视频的 hook：run 是红的，汇总却全绿；这里绝不译成 hook）。
5. **标题、meta.yaml 和配套文档用书面语体**：仓库、克隆、提交、推送、容器、镜像、钩子（hook）、流水线（pipeline）、工作流、持续集成（CI）、持续部署（CD）、拉取请求（PR）、机密（secret）、分支保护；job、runner、artifact、webhook 在书面语里也保留英文（video.yaml 的 publish.description_zh 就是这样写的）。

## 关键决定

- **job、runner、artifact 照说，两种语体都不译**（A1 c、A3、A4）：GitHub 中文文档写“作业”“运行器”“工件”，但实验课上没人这么说，课程的 publish 简介也写“六个 job”“runner”“artifact”。第 9 讲那一处“整个任务”（the whole job fails）被本片取代：这里 job 是每个场景屏幕上都有的 GitHub 对象。
- **工作流、步骤、事件、触发条件说中文**（A3）：GitHub 中文文档的标准译名，第 7、15 讲也用“工作流”；step 说“步骤”（Black 这一步、检查那一步），YAML 里的 `run`、`uses`、`steps` 作为键照抄。
- **run 照说**（A1 c、A7）：一次工作流运行说 run（整个 run 是红的；run 1、run 2、run 3 是视频里的标号；演示 commit 那次 run）；动词 run 说“运行 / 跑”；YAML 键 `run` 说“run 这个键”。书面写“运行”。
- **pull request 写 PR**（A15）：字幕短，实验课上也这么说（开一个 PR、PR 变红）；书面写“拉取请求（PR）”。merge → 合并（一次临时合并、合并按钮），和第 9 讲的“合并冲突标记”分开。
- **secret、webhook 照说**（A14）：仓库 secret；incoming webhook 是 Slack 自己的叫法；书面写“机密（secret）”。`SLACK_WEBHOOK_URL` 按旁白写成 Slack webhook URL（A6），它是 secret 的名字，绝不写它的值。
- **gate 仍是“门禁”，和第 9 讲一致**（A7）：script.md 给的比喻译法（“是铃，不是门”、行李箱、关卡、旁路、结果令牌）基本采用，只有 gate 不用“关卡”（那是第 4 讲三道认证关卡的词），沿用第 9 讲同一个 repo、同一个比喻的“门禁”：It's the bell, not the gate → 它是铃，不是门禁；every step is a gate that reads an exit code → 每个步骤都是一道读退出码的门禁。success tokens 不用“结果令牌”，直接写“三个 success”（A13）。
- **视频的 hook ≠ Git 的 hook**（A7）：S07[8] “here is the hook, on your own push” 和 S11[3] “here is the hook, answered” 指的是开头的谜题，译成“开头那个谜题”，绝不写 hook。
- **带下划线、括号、等号、$ 的实物按旁白写**（A6、B3）：`$GITHUB_OUTPUT` → GitHub output；`if: always()` → if always；`test_broken` → test 下划线 broken（第 9 讲的写法）；`def broken(): assert False` → def broken，assert False；`cheese-app-api:${{ github.sha }}` → cheese-app-api，冒号，再加 commit ID；`enabled=true` → enabled 为 true；`main -> main` → main 到 main；`***` → 三个星号。英文行用 en_display 给出字面形式（D4）。
- **视频的两个部分 ≠ README 的 Part**（A7）：视频的 part 1 / part 2 → 第一部分 / 第二部分；README 的 Part 4、Part 5、Part 6 照进度条写（before part 6 → 在做 Part 6 之前）。
- **勘误和说明，固定说法**（A10、D6）：A small slip → 有一个小疏漏（S06、S08、S15）；a small gap / One more gap → 一个小缺口 / 还有一个缺口（S10、S13）；A small note → 说明一点（S04）；A kind note → 提一句（S07）；One honest note → 如实说一句（S02）。都和英文一样温和、简短，不当成纠正谁。
- **思考题不泄底**（A10）：五道思考题（S04[2]、S07[4]、S08[8]、S11[6]、S13[10]）的题干不透露答案；揭晓时用题目自己的话回答（一个也没有；在，它在 main 上）。
- **Black、Flake8 首字母大写**：旁白和 `ci.yml` 的步骤名（Run Black formatter check、Run Flake8 linter）都大写；命令 black / flake8 仍小写（第 9 讲写的是命令）。

## 术语表

“字幕”是中文字幕行里的写法（标题和配套文档用 A4 的书面形式）；“首次出现”给出例句（SNN[k]：场景 SNN 第 k 段 SAY 里一个英文句子对应的一个中文句子，k 从 0 数），翻译 narration 时直接沿用，每一句都能通过检查器。“说明”一栏和 glossary.yaml 的 note 相同（多为英→中的用法对照和规则编号）。这个系列没有中文配音，所以没有第 1 讲的“朗读（say:）”一栏。

- **[G3]** 名字和命令绝不拆开。切分器把中文行里两个拉丁词之间的空格当成好切点，所以 git commit --no-verify -m "quick fix"、pre-commit run --all-files、git remote set-url origin、git checkout -b feature/test-protection、Lint and Format Check、Build Docker Image、Test Summary、Run unit tests、Load Docker image、Check test results、New repository secret、Secrets and variables、Require status checks to pass before merging、Require a pull request before merging、nothing to commit, working tree clean、pull access denied 和 Everything up-to-date 都可能被拆到两行。把它们放在分句末尾、全角冒号或顿号之后，周围少放中文，每条字幕最多一个长标签或长命令；.zh.srt 生成后，逐条检查带命令、job 名、步骤名或日志原文的字幕。
