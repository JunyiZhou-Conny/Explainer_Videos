## 为什么要中英混用

- 中国的 MLOps 工程师和助教带实验课时本来就中英混着说：“开一台 VM，SSH 进去”“push 到 registry”“前面放一个 nginx 做反向代理”“跑一下 pulumi up，先看 preview”“切到 dev 这个 stack”“state 存在 bucket 里”“provider 去调 API”“别随手加 -y”“不设 passphrase”“用 heredoc 写”。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A4）。
- 这是跟练视频：观众要照着敲命令，要在英文 README、终端、Google Cloud 控制台和代码面板里找东西。命令、参数、文件名和路径、container / 网络 / image 的名字、网络标记、角色名、控制台上的标签、日志和报错原文、状态码一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 Google Cloud 中文控制台和文档、Docker 和 nginx 中文资料、Kubernetes 中文文档里的标准译名，方便搜索：部署、反向代理、Web 服务器、防火墙、防火墙规则、网络标记、外部 IP、启动磁盘、服务账号、角色、密钥、访问令牌、私钥、公钥、基础设施即代码、期望状态、资源、构造函数、计划、声明式、单点故障、校验和、文件系统、格式化、重启策略、构建器。
- 双语字幕带把英文原句放在每行中文的正下方，所以中文行不加任何括注，也不给保留英文的词加中文解释。
- 这个系列不翻译画面：终端、代码面板、README 卡片和 expected 面板、示意的控制台 / Docker Hub / 浏览器窗口、V1–V8 的示意图、六步条、标签、进度条、课件标签、开头的谜题卡片、思考题和自测卡片都保持英文，只翻译旁白。

## 总原则

用一位中国 MLOps 助教在实验课上带同学一步步部署时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。观众已经会说“开一台 VM”“SSH 进去”“把 repo clone 下来”“起一个 container”“构建 image”“push 到 registry”“发布一个 port”“挂载一个目录”“进到 container 的 shell 里”“按 Ctrl-C”“报 404”“删掉 VM”；这一讲再加上“在前面放一个 nginx”“走反向代理”“剪掉前缀”“加网络标记”“开防火墙”“写成代码”“跑 pulumi up”“先看 preview”“切 stack”“存 state”“调 provider”“带 --refresh”“别随手加 -y”“进工具箱”“开 OS Login”“生成 SSH 密钥”“通过 SSH 部署 container”“跑 destroy”。每个选择都过三道关：实验课上真的这么说；是 Google Cloud 中文控制台和文档、Docker 和 nginx 中文资料、中文工程文献里能搜到的标准译名；和本系列一致（第 1–18 讲和考前精讲版定下的写法一律保留）。

## 关键决定

- **和 BRIEF 提示不同的地方：系列一致性优先**（A1、A3）。BRIEF 的 “Chinese glossary heads-up” 建议 VM、container、image、registry、Docker Hub、Artifact Registry、network、port、firewall、network tag、VPC、disk、nginx、reverse proxy、location、upstream、Pulumi、stack、project、config、state、backend、provider、resource、preview、refresh、destroy、Output、StackReference、service account、key、OS Login、SSH、passphrase、toolbox、timestamp tag 都保留英文。前几讲已经定成中文的，这里沿用：**网络**（第 4、10 讲）、**防火墙、反向代理**（考前精讲版第 16 讲）、**磁盘、启动磁盘、外部 IP**（第 1 讲）、**服务账号、角色、密钥**（第 10、14 讲）、**项目**（第 1、10 讲）、**部署**（第 14 讲）；script 自己的比喻表把 toolbox 定为**工具箱**。network tag 用 Google Cloud 中文控制台的**网络标记**；resource → **资源**，desired state → **期望状态**（Kubernetes 中文文档），plan → **计划**。其余是 Pulumi / Terraform 圈子里中文工程师真的说英文的词：stack、state、config、provider、backend、stack reference、provisioning、trigger、passphrase、heredoc、location、scopes。产品名（Pulumi、nginx、Docker Hub、Artifact Registry、OS Login）、实物（preview、up、destroy、--refresh、upstream 报错）本来就照抄。
- **state 照说，期望状态说中文**（A7、A8）：state 是 Pulumi 记下的“上次建了什么”（state 文件、state bucket），中文工程师说 state；desired state 是程序算出来的“应该是什么”，Kubernetes 中文文档叫期望状态；reality 是实际情况。S09[10] 的 Desired equals state equals reality → 期望状态等于 state，也等于实际情况，三者分得开。current state 只在 S09[4] 出现，译“当前状态”。
- **backend 只指 Pulumi 的 state 后端**（A7）：本地 backend、登录 bucket。第 18 讲的“后端”是应用的后端，这份稿子没有用到，两个词不混。
- **config 和配置分开**（A7）：Pulumi 的 config（config set、Pulumi 的 config 取代了 inventory.yml）照说；一般意义的配置（一份 Docker 配置、nginx 的配置文件）说中文。
- **provider 照说，output 说“输出”**（A7、A8）：provider 是 Pulumi 的插件，和第 14 讲的“服务方”（翻译服务的提供方）不是一回事；Pulumi 的 output 在字幕里是“输出”（六个输出；一个输出，一个密封的信封）。
- **provisioning 照说**（A1 c、A8）：中文“置备”“预配”在实验课上几乎没人说；字幕写 provisioning（第 4 步 provisioning），标题和配套文档写“置备（provisioning）”。S14[3] 的 provision it 按文件名的动作写成 provision 实例。
- **项目、repo、仓库三分**（A7）：GCP 项目和 Pulumi 项目都是“项目”；Git 的 repository 是 repo（这个 repo）；Artifact Registry 的 repository 是“仓库”（Artifact Registry 仓库、registry 仓库，同第 14 讲）；apt 的 repository 是“软件源”（Docker 的软件源、Google 的 apt 软件源）。
- **电话簿，不用通讯录**（policy 4）：script.md 建议 the phone book → 通讯录，但第 4、10、18 讲同一张图都叫电话簿，同一张图在系列里只有一个词。script 的其余比喻译法全部采用：唯一的公共入口、剪刀、指示灯、密封的信封、多米诺骨牌、管道、工具箱。
- **引用的终端原文照抄，去掉屏幕上的引号**（A13、B2）：syntax error near unexpected token newline、No such container、Compiled successfully、access denied、Welcome to AC215、loading CNN model、404 Not Found、pull access denied、has no installation candidate、Invalid grant: account not found（同第 18 讲，按屏幕的大小写和冒号，不按 SAY 的逗号）、No credentialed accounts、no such file、no active account、Updated、Created stack dev、Skipping preview build、403 Forbidden、200 OK。Pulumi 问的那句 do you want to perform this update 也照抄。课件上的横幅（Pulumi manages infrastructure through cloud APIs）和“别忘了删除”那页的话不是要对照的字符串，翻译。
- **带下划线和符号的实物**（A6、B3）：deploy_images → deploy images，deploy_single_vm → deploy single VM，create_instance 等四个文件 → create instance、provision instance、setup containers、setup webserver，retain_on_delete → retain on delete，instance_ip → instance IP，docker_build.Image → docker build Image，log_format → log format，GCP_PROJECT → GCP project 变量，PULUMI_ACCESS_TOKEN must be set → Pulumi access token must be set，计划里的 + ~ - +- → 加号、波浪号、减号、加减号，README 的 <…> → 占位符 / 尖括号，Ctrl+C → Ctrl-C；英文行用 en_display 给出字面形式（D4）。检查器收的照写：|| true、sa_、blkid、mkfs、organization/deploy-images/dev、-i /secrets/ssh-key-deployment。
- **“幂等”不进字幕**（A8，同第 1 讲）：safe to run again / safe to run twice → 可以放心重跑 / 跑两次也安全；“幂等”只在配套文档里用。
- **勘误和说明，固定说法**（A10、D6）：A small slip → 有一个小疏漏（S05 Chroma 存在 /data；S12 inventory.yml；S15 SSH 命令漏了密钥）；A small note / One note → 说明一点（S02 /status；S15 Gemini 模型）；One honest note → 如实说一句（S01，录制环境的说明，系列用语）；One step is missing from the README → README 漏了一步（S10）；课件和录屏不一致的地方（箭头方向、四个 container、GCR、前端在 80）都和英文一样温和、简短，不当成纠正谁。
- **阶段和步骤分开**（A16、C1）：课上手动部署的四个 stage → 第 1–4 阶段（第一部分）；课件第 19 页的六个 step → 第 1–6 步（第二部分，旁白说的 step n 只指它们）；README 的步骤按小节名说，进度条上的编号不念。
- **思考题不泄底**（A10）：五道思考题（S05[6]、S07[9]、S09[9]、S14[10]、S15[8]）的引子和题干不能透露答案，“A question.” 一律是“想一想。”（同前几讲）；揭晓时用题目自己的话回答（不会。/ 不能。/ 什么都不用做。/ 因为格式化会清空数据。/ gcp-service 的密钥）。
- **“your turn”和“录制时”**（A10、A11、D6）：屏幕标签 your turn 照抄，旁白里的 pause and run it → 暂停一下，跑一遍；at the time of recording → 录制时（版本号只在屏幕上）；Ours … ; yours … → 我们的……；你的……，从 S01[7] 说过一次录制环境以后，每个云端报错都只是下一行。

## 术语表

“字幕”是中文字幕行里的写法（标题和配套文档用 A4 的书面形式）；“首次出现”给出例句（SNN[k]：场景 SNN 第 k 段 SAY 里一个英文句子对应的一个中文句子，k 从 0 数），翻译 narration 时直接沿用，每一句都能通过检查器。“说明”一栏和 glossary.yaml 的 note 相同（多为英→中的用法对照和规则编号）。这个系列没有中文配音，所以没有第 1 讲的“朗读（say:）”一栏。
