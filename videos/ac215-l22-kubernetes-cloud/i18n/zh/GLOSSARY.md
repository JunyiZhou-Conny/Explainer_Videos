## 为什么要中英混用

- 中国的 MLOps 工程师和助教带 Kubernetes 实验课时本来就中英混着说：“起一个 Pod”“写个 Deployment”“前面挂一个 Service”“打个 label，用 selector 选”“切到这个 namespace，记得加 -n”“这个 Job 跑完了”“requests 设多少”“扩到 3 个副本”“节点池自动扩缩”“配一下 Ingress”“kubeconfig 没了，重新 get-credentials”“exec 进 Pod 看看”。Kubernetes 中文文档自己也保留 Pod、Deployment、Service 这些对象类型的英文名。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A4）。
- 这是跟练视频：观众要照着敲命令，要在英文 README、终端、控制台和代码面板里找东西。命令、参数、文件名和路径、对象名、namespace、label、集群名、可用区和区域、状态词（Pending、Running、Completed）、日志和报错原文一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 Kubernetes 中文文档和 GKE 中文控制台的标准译名，方便搜索：集群、节点、工作节点、控制平面、调度器、控制器、节点池、副本、期望状态、自愈、故障转移、负载均衡、负载均衡器、扩展、自动扩缩器、编排、私有网络、子网、路由器、NAT 网关、区域集群、主机名、重定向、占位符、弃用警告、服务账号。
- 双语字幕带把英文原句放在每行中文的正下方，所以中文行不加任何括注，也不给保留英文的词加中文解释。
- 这个系列不翻译画面：终端、代码面板、README 卡片和 expected 面板、示意的控制台和浏览器窗口、V1–V8 的示意图、三个诉求的勾选卡片（Failover / Load balancing / Scaling）、kubectl 语法卡片、标签（包括 `stand-in: kind, not GKE`）、进度条、课件标签、思考题和自测卡片都保持英文，只翻译旁白。

## 总原则

用一位中国 MLOps 助教在实验课上带同学一步步把应用部署到 Kubernetes 时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。观众已经会说“开一台 VM”“SSH 进去”“把 repo clone 下来”“起一个 container”“构建 image”“push 到 registry”“进工具箱”“跑 pulumi up”“先看 preview”“切 stack”“存 state”；这一讲再加上“建一个集群”“加节点”“起一个 Pod”“写一个 Deployment”“挂一个 Service”“打 label”“按 selector 找 Pod”“切 namespace”“加 -n”“跑一个 Job”“申请 requests”“扩到 3 个副本”“节点池自动扩缩”“配 Ingress”“走 Ingress controller”“装 Helm chart”“连 kubeconfig”“exec 进 Pod”“看 Job 的日志”。每个选择都要过三关：实验课上真的这么说；有标准、能搜到的中文名（Kubernetes 中文文档、GKE 中文控制台、通用工程用语）；和系列一致（第 1–21 讲和考前精讲版，尤其是第 20 讲：定下的写法一律沿用）。

## 关键决定

- **对象类型保留英文，架构用中文**（A1 c、A3、A8）：Pod、Deployment、ReplicaSet、Service、Job、Ingress、PVC 是对象类型名，Kubernetes 中文文档和工程师都直接说英文；集群、节点、工作节点、控制平面、调度器、控制器、节点池用中文文档的标准译名。组件名 API server、etcd、kubelet、kube-proxy、containerd 照写；scheduler 一律说“调度器”，只有 S05[7] 按 Pod 名点到的 controller manager 照写。
- **namespace、label、selector、requests 字幕里照说**（A1 c、A4、A7）：namespace 在命令里天天要敲（-n），实验课上没人说“命名空间”；label 保留英文还有一个好处：和屏幕上的灰色 / 黄色“标签”（tag）分开；requests 保留英文，和 HTTP 的“请求”分开（负载均衡里的 requests spread across copies 是“请求”）。标题和配套文档写“命名空间（namespace）”“标签（label）”“资源请求（requests）”。
- **Service ≠ 服务，Deployment ≠ 部署，控制器 ≠ Ingress controller**（A7）：Kubernetes 对象 Service 照写，“服务”只用于一般意义（Pulumi 自己的云服务），service account 是“服务账号”，API 的 api-ksa 是“Kubernetes 服务账号”；Deployment 对象照写，动词和活动是“部署”（S02[2] 用“部署”加引号点明这一区别）；控制平面里的 controllers 是“控制器”，NGINX Ingress controller / nginx controller 保留英文，两者不混。
- **cloud provider ≠ provider**（A3、A7）：S06[7] 控制器等的是“云平台”；provider 只指 Pulumi 的插件（一个 Kubernetes provider）。
- **state、状态、期望状态三分**（A7）：Pulumi 的 state 照说（同一个 state bucket）；etcd 里存的是集群的“状态和配置”；desired state 是“期望状态”（同第 20 讲）。
- **副本、扩展、自动扩缩器**（A7、A8，同第 13、16 讲）：copies 和 replicas 都是“副本”；Scaling 这个诉求是“扩展”，scale to 3 是“扩到 3 个”，scale back 是“缩回”；autoscaler 是“自动扩缩器”（Kubernetes 中文文档的“自动扩缩”），Pod autoscaler 是“Pod 自动扩缩器”。
- **区域 ≠ 可用区**（A3，同第 1 讲）：S14[1] 的要点就是 --zone 和 --region 的区别，字幕写“代码把区域传给了 --zone 参数；写成 --region，才名副其实”。
- **三个诉求和五个好处**（A16）：课上的 three asks 是“三个诉求”（S01[6] 的 three jobs 是“三件事”）：故障转移、负载均衡、扩展；five payoffs 是“五个好处”：自助服务、成本更低、自动调整、运行平稳、开发更简单。屏幕上的勾选卡片保持英文。
- **故事里的角色**（A16）：the app owner → 应用负责人，the operator → 运维；从不用人名。README 里的 Pod 名字“是作者自己的”，也不点名。
- **带下划线和符号的实物**（A6、B3）：deploy_images → deploy images，deploy_k8s → deploy k8s，setup_containers.py → setup containers，create_cluster.py → create cluster，ip_address → ip address，nginx_ingress_ip → nginx ingress ip，app_url → app URL，ROOT_PATH → ROOT PATH 变量，PULUMI_ACCESS_TOKEN must be set → Pulumi access token must be set（同第 20 讲），--replicas=4 → replicas 设成 4，<pod-name> → pod name 占位符 / 尖括号，EXTERNAL-IP <pending> → 外部 IP 显示 pending，计划里的 + 4 / + 23 → 要创建 4 个 / 23 个；英文行用 en_display 给出字面形式（D4）。检查器收的照写：run: web、gcp:project、web.default.svc.cluster.local、IP.sslip.io、-n cheese-app-namespace、-c wait-for-chromadb、Create & Deploy Cluster。
- **引用的终端原文照抄，去掉屏幕上的引号**（A13）：404 Not Found、pull access denied、No credentialed accounts、no active account、connection refused、Created stack dev、Pulumi access token must be set、NoneType object is not subscriptable、Invalid grant: account not found（同第 18、20 讲）、Multi-Attach、200 OK、502 / 503，以及状态词 Pending、Running、Completed、Ready、healthy、active、rolled out、done、Succeeded。旁白转述的部分（全都会失败、找不到这个 namespace、同样的令牌报错）说中文。
- **勘误和说明，固定说法**（A10、D6）：A small slip → 有一个小疏漏（S04 Google Container Registry 已关停；S13 README 的虚线箭头方向）；A small note → 说明一点（S03 课件写的运行时是 Docker；S15 数据库重启后重跑加载器）；A small surprise → 有个小意外（S04 dispatcher）；One honest note → 如实说一句（S02，录制环境的说明，系列用语）；A word of warning → 提醒一句；Two one-time steps the README leaves out → README 漏掉了两个一次性的步骤；README 的输出“比代码稍旧一点”。都和英文一样温和、简短，不当成纠正谁。
- **估算就说估算**（A10）：S09 的每天 5 到 8 美元、S12 的一刻钟或更久都是“按我们的估算”；S10 的 Service Account Admin 角色“这一点我们没法测试”。
- **思考题不泄底**（A10）：五道思考题（S01[4]、S06[6]、S07[5]、S13[8]、S15[8]）的题干不能透露答案；揭晓时用题目自己的话回答（是机器本身 / 是控制器，在等云平台 / 两个。/ 回答的是 nginx controller：404 Not Found / 它们一直卡在创建中）。
- **“your turn”、“额外”和“录制时”**（A10、A11、D6）：屏幕标签 your turn 照抄，旁白里的 pause and run it → 暂停一下，跑一遍；extra → 额外（一个额外检查、在这里是额外步骤、再一个额外的）；at the time of recording → 录制时（版本号只在屏幕上）；Ours … ; yours … → 我们的……；你的……，从 S02[6] 说过一次录制环境以后，每个云端报错都只是下一行。kind 替身在 S05[2] 说一次，之后都叫“替身”或“这个 kind 集群”。

## 术语表

“字幕”是中文字幕行里的写法（标题和配套文档用 A4 的书面形式）；“首次出现”给出例句（SNN[k]：场景 SNN 第 k 段 SAY 里一个英文句子对应的一个中文句子，k 从 0 数），翻译 narration 时直接沿用，每一句都能通过检查器。“说明”一栏和 glossary.yaml 的 note 相同（多为英→中的用法对照和规则编号）。这个系列没有中文配音，所以没有第 1 讲的“朗读（say:）”一栏。
