## 为什么要中英混用

- 中国的 MLOps 工程师和助教带实验课时本来就中英混着说：“起一个 uvicorn”“加一个 router”“看一下 /api/docs”“/readyz 还是 503”“带上 session ID”“node modules 放在一个 volume 里”“同一个 origin，所以不用 CORS”“先 stash 一下”“报 422 了”。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A4）。
- 这是跟练视频：观众要照着敲命令，要在两份英文 README、终端、浏览器和代码面板里找东西。命令、参数、文件名和路径、URL、container / 网络 / image 的名字、日志里的原文、状态码、README 的小节名、应用的标签页和聊天模式一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 MDN 中文版、Kubernetes 中文文档和中文工程文献里的标准译名，方便搜索：前端、后端、浏览器、服务器、请求、响应、状态码、请求头、路由、中间件、装饰器、类型提示、查询字符串、重定向、静态文件、缓存、强制刷新、单页应用、组件、框架、开发服务器、构建工具、代理、预检请求、探针、存活、就绪、集群、挂载、构建缓存。
- 双语字幕带把英文原句放在每行中文的正下方，所以中文行不加任何括注，也不给保留英文的词加中文解释。
- 这个系列不翻译画面：终端、代码面板、README 卡片和 recorded / expected 面板、示意的浏览器窗口、V1–V8 的示意图、标签、进度条、课件标签、思考题和自测卡片都保持英文，只翻译旁白。

## 总原则

用一位中国 MLOps 助教在实验课上带同学一步步操作时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。观众已经会说“把 repo clone 下来”“起一个 container”“构建 image”“发布一个 port”“进到 container 的 shell 里”“跑 pytest”“看横幅”“按 Ctrl-C”“报 500”；这一讲再加上“起 uvicorn”“加一个路由”“挂一个 router”“看 /api/docs”“/readyz 返回 503”“带上 session ID”“放进一个 volume”“同一个 origin”“走 Vite 代理”“打 prod 的 tag”“先发一个预检”“stash 一下”。每个选择都过三道关：实验课上真的这么说；是 MDN、Kubernetes、Docker 中文文档和中文工程文献里能搜到的标准译名；和本系列一致（第 1–17 讲和考前精讲版定下的写法一律保留）。

1. **实物原样**：观众要输入、要在屏幕上对照的东西（命令、参数、文件名和目录名、路径和 URL、container / 网络 / image / volume 的名字、包和工具名、作为标题点名的 README 小节、应用的标签页和聊天模式、旁白引用的日志和报错原文、状态码）逐字照抄，不翻译、不变形、不加引号。检查器逼出来的例外（实物里有下划线、= & + 或括号）按旁白的说法写（A6），英文行显示原样（D4）。画面上的一切都是英文，只翻译旁白。

## 关键决定

- **和 BRIEF 提示不同的地方：系列一致性优先**（A1、A3）。BRIEF 的 “Chinese glossary heads-up” 建议 API、REST API、FastAPI、uvicorn、route、router、prefix、endpoint、request、response、status code、query、header、JSON、port、published port、container、image、network、volume、bind mount、Docker Compose、Chroma、vector DB、embedding、RAG、CNN、Gemini、probe、liveness、readiness、session ID、frontend、backend、HTML、CSS、JavaScript、React、Vite、React Router、component、JSX、single-page app、dev server、proxy、nginx、origin、CORS、preflight、build、`dist`、branch、stash、pytest 都保留英文。前几讲已经定成中文的，这里沿用：**路由**（第 9、10 讲）、**请求、响应、状态码**（第 14 讲）、**请求头**（第 10 讲）、**网络**（第 4、10 讲）、**挂载**（第 2–4 讲）、**构建**（第 2 讲）、**分支**（第 1 讲）、**前端、后端、代理**（考前精讲版第 16 讲）、**向量数据库**（第 5 讲）、**查询字符串**（第 14 讲）。其余按 MDN 和 Kubernetes 中文文档的标准译名说中文：**探针、存活、就绪、组件、单页应用、开发服务器、预检、中间件**——这些在中文前端圈和 K8s 圈都是日常说法，不生硬。照提示保留英文的：产品和工具名、API、JSON、HTML、CSS、JavaScript、JSX、container、image、port、volume、embedding、chunk、stash、session ID、router、origin、CORS。
- **router 照说，route 是“路由”**（A1 c、A7）：FastAPI 的 APIRouter 和 React Router 的 router 在实验课上都说 router；“路由器”是网络硬件（考前精讲版第 16 讲就是这么用的），而“路由”已经给了 route。所以“三个聊天 router”“一组路由”分得开。
- **origin 照说，书面写“源（origin）”**（A1 c、A4）：“源”单独出现在字幕里容易读成“来源”，“域”又不准确（origin 包含协议和 port）。字幕写 origin，“同源策略”“跨域”只在配套文档里用。
- **session ID 照说**（A15）：请求头叫 X-Session-ID，第 6 讲也保留了 session；“会话 ID”只用在书面语。
- **许可条、信使、电话簿**（policy 4）：script.md 给了图的译法建议（permission slip → 许可条；the courier → 信使；three and a half → 第 3.5 步；step zero, the preflight → 第 0 步，预检；the leaves of this tree → 这棵树的叶子；stamps out → 批量生成），全部采用；只有 phone book 不用建议的“通讯录”，而沿用第 4、10 讲的“电话簿”，同一张图在系列里只有一个词。
- **引用的日志、代码和报错原文照抄**（A13）：这份稿子里旁白引用的都是屏幕上的原文（Application startup complete、CNN model is loading、Invalid grant: account not found、Internal Server Error、Newsletter not found、host not found in upstream、How is cheese made、use Gemini to generate text、Welcome to AC215、26 passed），观众要在终端里找它们，所以照屏幕写，Invalid grant 一句按屏幕的大小写和冒号写，不按 SAY 的逗号。唯一翻译的引语是 S01[4] 课上那句自嘲（well, not really, we need to build it → 其实还没有，我们得把它建出来）：它不是要对照的字符串，英文行就在下面。
- **localhost 写成要输入的样子**（A6）：和第 14 讲（localhost 8086 照旁白）不同，这里写 localhost:9000、localhost:3000、localhost:8080：script.md 的 en_display 表把它们还原成带冒号的形式，检查器也收冒号，观众要把它敲进地址栏（第 10 讲、考前精讲版第 16 讲也这样写）。同理路径直接写成路径（/api/docs、/api/llm/chats、src/vector-db）。
- **带下划线和等号的实物**（A6、B3）：square_root → square root，get_status → get status，api_server → API server，uvicorn_server → uvicorn server（第 10 讲），node_modules → node modules，x=2&y=10 → x 等于 2，y 等于 10，Ctrl+C → Ctrl-C；英文行用 en_display 给出字面形式（D4）。
- **勘误和说明，四个固定说法**（A10、D6）：A small slip → 有一个小疏漏（S03、S05、S13）；A small note → 说明一点（S05、S06、S09、S14）；One kind note → 提一句（S03，课件把 container 内部标成 localhost 9000）；One honest note → 如实说一句（S06，系列用语）。都和英文一样温和、简短，不当成纠正谁。
- **v1 / v2、main 分支、2025 分支、教程 24**（A16、C1）：cheese app version 1 / 2 在旁白里是 repo 时写 cheese-app-v1 / cheese-app-v2，说版本时写 v1 / v2；main 永远带“分支”（main 分支），并且不开句；Tutorial 24 → 教程 24（课程的编号，屏幕上的标题保持 Tutorial (24): Simple Frontend App）。
- **README 小节名：完全一致的照抄，简称就翻译**（A1 a、A16）：Backend APIs、Review the code、Review the app、Docker Cleanup、Home page、Newsletter feature、Chat feature 和 README 的标题一致，照抄；Demo route（标题是 Create a demo route）、API docs（View API docs）、React setup（Tutorial: React Frontend Setup）是旁白的简称，译成演示路由、API 文档、React 前端设置。
- **思考题不泄底**（A10）：五道思考题（S03[12]、S07[9]、S11[4]、S12[7]、S15[10]）的引子和题干不能透露答案；揭晓时用题目自己的话回答（在 container 里面，可以……不行；等；不能。；是 origin。）。

- **[G1]** 宽度。双语字幕带：中文一行最多 30 个单位，英文一行 96 个字符；纯中文字幕（.zh.srt）一行 22 个单位，每条两行。分句不超过大约 24 个单位，用 ，；：、 隔开，让切分器有干净的切点；不要写超过 30 个单位又没有标点的分句。长实物（D8）单独占一个分句；S01[3]、S03[6]、S07[2]、S08[1]、S10[6]、S11[1]、S14[4]、S16[1] 这几个长句，在英文每个分句的断点都加逗号。
- **[G2]** 字幕条结尾：工具链去掉每条字幕末尾的 。，、；：，保留 ？！…… 和收尾的 ”（subtitles.strip_end）。英文允许时，分句尽量以中文词收尾（……放进 secrets 目录里。比 ……secrets。好读）；引用的日志原文（Invalid grant: account not found、host not found in upstream、26 passed）可以像英文那样放在句末。
- **[G3]** 名字和命令绝不拆开。切分器把中文行里两个拉丁词之间的空格当好切点，所以 Application startup complete、Invalid grant: account not found、Internal Server Error、host not found in upstream、docker compose up --build、sh docker-shell.sh、npm run dev、npm run check、git switch 2025、git stash pop、Cheese books、Review the code、Review the app、Vertex AI User 都可能被切到两行。把它们放在分句末尾、全角冒号或顿号后面，周围少放中文，每条字幕最多一个长标签；渲染出 .zh.srt 后，检查每条含命令、日志原文或小节名的字幕。
