## 为什么要中英混用

- 中国的 MLOps 工程师和助教带实验课时本来就中英混着说：“部署成一个 Cloud Run service”“跑一个 job”“等 revision 就绪”“设 1 个 task”“按 Enter 生成一个 chip”“看 digest”“impersonate 运行时账号”“看一下 manifest”“报 403 了”。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A4）。
- 这是跟练视频：观众要照着敲命令，要在英文 README、Google Cloud 控制台、终端和浏览器里找东西。命令、参数、文件名、service / job / 账号的名字、角色名和 API 名、控制台上的标签和按钮、应用的按钮、演示字符串、状态码、区域名一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 Google Cloud 中文文档和控制台、中文工程文献里的标准译名，方便搜索：函数、入口点、实例、冷启动、最小实例数、最大实例数、并发数、按请求计费、缩容到零、区域、服务账号、角色、主账号、配额项目、组织政策、应用默认凭据、软删除、禁止公开访问、统一访问、存储类别、处理函数、装饰器、查询字符串、网络接口、环境变量、线程、主进程、模拟运行、厂商锁定。

## 总原则

用一位中国 MLOps 助教在实验课上带同学一步步操作时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。观众已经会说“把 repo clone 下来”“起一个 container”“构建 image”“打 tag”“看 digest”“发布一个 port”“建一个 bucket”“建一个服务账号”“走 ADC”“调一个 endpoint”“报 403”；这一讲再加上“部署成一个 Cloud Run service”“跑一个 job”“serverless 部署”“等 revision 就绪”“1 个 task”“按 Enter 生成一个 chip”“新的 attempt 目录”“impersonate 运行时账号”“看 manifest”。每个选择都过三道关：实验课上真的这么说；是 Google Cloud 中文文档和控制台、中文工程文献里能搜到的标准译名；和本系列一致（第 1–13 讲和考前精讲版定下的写法一律保留）。

1. **实物原样**：观众要输入、要在屏幕上对照的东西（命令、参数、文件名和目录名、service / job / 账号的名字、角色名和 API 名、控制台的标签和按钮、应用的按钮、演示字符串、状态码、区域、作为标题提到的 README 小节名）逐字照抄，不翻译、不变形、不加引号。检查器逼出来的例外（实物里有下划线、+ 或括号）按旁白的说法写（A6），英文行显示原样（D4）。旁白转述的报错信息译成中文（A13），终端和英文行保留原文。画面上的一切都是英文，只翻译旁白。

## 关键决定

- **和 BRIEF 提示不同的地方：系列一致性优先**（A1、A3）。BRIEF 的 “Chinese glossary heads-up” 建议 serverless、Cloud Run、Cloud Run functions、Cloud Build、Artifact Registry、function、entry point、functions-framework、gunicorn、revision、instance、cold start、scale to zero、concurrency、min/max instances、request-based billing、service、job、task、execution、image、tag、digest、container command/arguments、chip、argv、service account、runtime identity、ADC、impersonation、IAM、role、bucket、prefix、manifest、query string、endpoint 都保留英文，并且只在 serverless 第一次出现时旁边写“无服务器”。其中考前精讲版或前几讲已经定成中文的，这里沿用：**函数、入口点、实例、冷启动、缩容到零、最小 / 最大实例数、按请求计费、执行、服务账号、角色**（考前精讲版、第 3 讲）、**前缀**（第 3 讲）、**查询字符串**（第 4 讲）。concurrency 用 Google Cloud 中文文档的“并发 / 并发数”。其余照提示保留英文（产品名、image、tag、digest、bucket、manifest、endpoint、ADC、IAM、revision、task、chip、impersonate）。“无服务器”只用在标题和配套文档里：字幕里写它就得加括号，而双语字幕带下面本来就有英文。
- **revision、task、chip、attempt 照说**（A1 c、A15）：revision 是控制台上的词（Revision History），中文文档的“修订版本”在口语里太生硬；task 是 job 的单位（1 个 task、Tasks 标签页），“任务”在系列里已经是第 13 讲的训练任务；chip 是控制台的输入块，画面上就是一个个 chip；attempt 是进度条上的 Attempt folder。书面语里分别写 修订版本（revision）、任务（task）。
- **task 超时，不是任务超时**（A15）：考前精讲版写的是“任务超时”，指的是同一个字段；这一讲同时数 task、打开 Tasks 标签页，为了前后一致写“task 超时”。
- **impersonate 照说，不用“模拟”**（A1 c、A14）：Google 中文文档把 impersonation 叫“服务账号模拟”，可“模拟运行”在第 13 讲和本片 S07 里已经用来说 Apple Silicon 上的 emulation，两个“模拟”挨得很近会混；“冒充”语气不对。字幕写 impersonate（只用原形），书面语写 服务账号模拟（impersonation）。
- **令牌，不是 token**（A14）：考前精讲版有一处保留了 token；这一讲有三句讲令牌（向身份验证库要一个令牌、短期令牌、在 Cloud Run 上找到令牌），按第 10、11 讲的系列写法用“令牌”。
- **入口点和 entrypoint 分开**（A7）：Cloud Run 函数的 entry point（控制台字段 Function entry point）说“入口点”；Docker image 的 ENTRYPOINT 槽位说 entrypoint（第 11、13 讲）；控制台的 Container command 填的正是 entrypoint 那个位置。Docker 的 CMD 说“命令”（命令那个位置、默认命令）。
- **覆盖参数和覆盖分开**（A7）：gcloud 的 overrides → 覆盖参数（总带“参数”）；overwrite → 覆盖（后面跟文件或结果）。
- **两扇门、一个管道**（A2、A14）：S07 的 -p 映射，旁白先说 the door（门，第 4、10 讲），后面又说 the pipe（管道）；S09 身份的两扇门也是“门”。按旁白各用各的词。
- **11 用阿拉伯数字**（C1）：旁白说 eleven，画面上是 11 个 chip，gcloud 命令框里是 11 个值，所以全片写“11 个”，包括 S16 第四题。
- **带下划线的名字**（A6、B3）：hello_http → hello 下划线 http（同考前精讲版），translation_demo serve → translation demo serve，三个环境变量写成 ENABLE SPEECH / GOOGLE CLOUD PROJECT / GOOGLE CLOUD LOCATION，Ctrl+C → Ctrl-C（第 9 讲的写法）；英文行用 en_display 给出字面形式（D4）。
- **“gcloud 替代做法”不开句**（A5、D6）：句子不能以小写的 gcloud 开头，所以 The gcloud alternative … 一律写成“用 gcloud 的替代做法，……”；Now the gcloud alternative. → 再看 gcloud 替代做法。
- **报错信息译成中文**（A13）：方法不允许（405）、语音已关闭（503）、Google 凭据不可用（503）、找不到可执行文件、连接被重置、main.py 里应该有一个叫 translate 的函数，但它找到的是 hello 下划线 http；状态码和状态词 complete、helper 打印的 downloaded results 照抄。
- **思考题不泄底**（A10）：五道思考题（S05[6]、S08[6]、S09[2]、S13[9]、S14[6]）的引子和题干不能透露答案；揭晓时用题目自己的动词回答（不能。/ 不会。）。
- **服务方、外部服务和 service 分开**（A7）：googletrans 背后的翻译服务是“外部服务 / 服务方”；Cloud Run 的资源是 service；service account 是“服务账号”。
