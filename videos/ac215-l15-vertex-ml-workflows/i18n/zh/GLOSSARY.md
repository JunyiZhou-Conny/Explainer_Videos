## 为什么要中英混用

- 中国的 MLOps 工程师和助教带实验课时本来就中英混着说：“建一个 bucket”“调 endpoint”“把 image push 到 ECR”“pin 住版本”“看一下 lock 文件”“upsert pipeline 的定义”“把 S3 换成一个 stub”“复制角色的 ARN”。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A8）。
- 这是跟练视频：观众要照着敲命令，要在英文 README、AWS 控制台、终端里找东西。命令、参数、文件名、用户 / 角色 / bucket 的名字、pipeline 的步骤名、控制台标签、模型的 label、终端打印的短报错、区域和实例类型一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 AWS 中文控制台和文档、TensorFlow 和中文机器学习文献里的标准译名，方便搜索：IAM 用户、角色、策略、访问密钥、凭据、令牌、区域、域、快速设置、停用、实例、签名、预处理、缩放、归一化、浮点数、概率、准确率、计算图、权重、导出、编排器、工作流管理、托管、调度、缓存、属性引用、步骤、边。

用一位中国 MLOps 助教在实验课上带同学一步步操作时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。观众已经会说“把 repo clone 下来”“起一个 container”“构建 image”“打 tag”“建一个 bucket”“调一个 endpoint”“跑一条 pipeline”“pin 住版本”“看 lock 文件”；这一讲是系列里第一次讲 AWS，再加上“一个 IAM 用户和一个角色”“访问密钥”“复制 ARN”“一个 S3 bucket”“endpoint 配置”“push 到 ECR”“upsert pipeline 的定义”“换成一个 stub”。每个选择都过三道关：实验课上真的这么说；是 AWS 中文控制台和文档、TensorFlow 和中文机器学习文献里能搜到的标准译名；和本系列一致（第 1–14 讲和考前版定下的写法一律保留）。

## 关键决定

- **和 BRIEF 提示不同的地方：系列一致性和 AWS 中文控制台优先**（A1、A3）。BRIEF 的 “Chinese glossary heads-up” 建议 SageMaker、S3、bucket、IAM、user、role、access key、ARN、policy、endpoint、endpoint configuration、Model、container、image、Docker、ECR、Lambda、pipeline、step、Processing job、Training job、property reference、DAG、cache、SavedModel、signature、`serving_default`、TFRecords、Pipfile、lock、pin、Vertex AI、Kubeflow、DSL、SDK 都保留英文。其中前几讲、考前版或 AWS 中文控制台已经有定论的，这里用中文：**角色**（第 14 讲）、**策略、IAM 用户、访问密钥**（AWS 中文控制台；密钥是第 1、3、14 讲的写法）、**步骤、属性引用、签名**（考前版）、**缓存**（第 8 讲）、**训练任务**（第 13 讲），以及与之配套的**处理任务**；endpoint configuration 说 **endpoint 配置**（endpoint 照说，“配置”说中文）；SageMaker 的 Model 就说“模型”（SageMaker 里的模型）。其余照提示保留英文（产品名和格式名、bucket、ARN、endpoint、container、image、pipeline、DAG、SavedModel、TFRecords、Pipfile、pin、SDK、DSL）；lock 按第 1 讲说“lock 文件”，serving_default 按旁白写成 serving default（A10）。
- **账号，不是账户**（A3、A16）：AWS 中文控制台写“账户”，本系列从第 1 讲起一直写“账号”（服务账号、Google 账号），这里沿用：AWS 账号、账号 ID、账号查询。
- **push、upsert、stub、socket 照说**（A1 c）：push 是 README 的 Build & Push，实验课上就说“push 到 ECR”；upsert 是 SDK 的方法名，“插入或更新”太生硬；stub 是 S06 的抓包替代（画面标签 capture stub），和 S08 的本地替身（TF Serving）是两回事，所以不都叫“替身”；socket 是挂进 workflow container 的 Docker socket。书面语分别写 推送、upsert（插入或更新）、桩（stub）。
- **processor 只在 S14 照说**（A6、A11）：S14 里 SDK 用你 ECR 的 image 建的是一个 Processor 对象，旁白说 a processor；其余地方的 processor 是 pipeline 的第二个阶段，说“数据处理器 / 处理器”（考前版）。
- **签名分两种**（A11）：模型的 signature 是名词“签名”（S05、S06、S08、S12，图上叫“前门”）；S03 里笔记本“给每个请求签名”是动词，只出现一次，不会混。
- **三个“入口”分开**（A11）：SavedModel 里“有名字的入口”（S06）；Docker 的 entrypoint（S11 的 entrypoint 脚本、S14 Processor 的 entrypoint）照说；第 14 讲函数的“入口点”本片不用。
- **job 一律“任务”**（A6）：训练任务（第 13 讲）、处理任务、给每个任务用；控制台标签 Training jobs、Processing jobs 照写。README 的 step 是“第 n 步”，pipeline 的 step 是“步骤”（处理步骤、模型步骤、Lambda 步骤）。
- **短报错照抄，转述译中文**（A12）：exec format error、Unable to locate credentials、AWS not configured、Permission denied 是观众要对照的终端原文，照抄；旁白自己说的 no credentials、AWS rejects our fake key 等译成“没有凭据”“AWS 拒绝了我们的假密钥”。
- **星号和小于 3**（A5、A10）：Pipfile 里的 `"*"` 旁白说 star，字幕写“星号”；`"<3"` 旁白说 less than 3，字幕写“小于 3”（检查器不收 <），英文行用 en_display 显示原样。
- **data collector 参数**（A10）：`--data_collector` 带下划线，检查器不收；写成“--data collector”又会让观众照敲出错，所以写“带上 data collector 参数，跑 python cli.py”，英文行显示 `--data_collector`。
- **150528 不加千位分隔符**（C1）：同第 8、14 讲；英文行和章节标题保留 150,528。
- **思考题不泄底**（A14）：四道思考题（S04[5]、S08[1]、S09[4]、S15[5]）的题干不能透露答案；揭晓时用题目自己的量词或动词回答（一个。/ 不会。）。
- **课件和教程不一致时平实地说**（A14、A17）：课件讲 Vertex AI，教程是 AWS 版；课件和两份 README 说模型注册表，代码建的是普通模型；课件画四个步骤，这里部署拆成两步——都按英文的语气说，不是纠正谁。
