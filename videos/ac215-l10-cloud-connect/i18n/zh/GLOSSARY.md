## 为什么要中英混用

- 中国的 MLOps 工程师和助教带实验课时本来就中英混着说：“建个服务账号，下个 JSON 密钥”“走 ADC”“换一个 bearer token”“查一下 IAM”“报 403 了”“跨域了，CORS 没配”“看一下 origin”“Docker DNS 解析不到”“起一个 container”“发布一个 port”“调 embedding 模型”“建一个 collection”。这些在实验课上本来就用英文说的词，字幕里照说；书面词留给标题、章节名和配套文档（A4）。
- 这是跟练视频：观众要照着敲命令，要在英文 README、Google Cloud 控制台、终端、浏览器和代码里找东西。命令、参数、文件名、路径、image / container / 网络 / collection 的名字、地址和 port、服务账号名、角色名、控制台标签、错误信息、状态码、请求头名字一旦翻译，就和屏幕对不上了。所以**实物原样，讲解用中文**。
- 已经有通用中文说法、工程师也这么说的概念一律说中文，用 Google Cloud 中文文档、MDN 中文文档和网络教材里的标准译名，方便搜索：服务账号、密钥、私钥、公钥、签名、凭据、应用默认凭据、访问令牌、元数据服务器、身份联合、最小权限、身份验证、授权、角色、权限、网络、回环地址、跨域、同源、预检请求、请求头、挂载、幂等、分块、向量化。
- 双语字幕带把英文原句放在每行中文的正下方，所以中文行不加任何括注，也不给保留英文的词加中文解释。
- 这个系列不翻译画面：终端、代码面板、README 卡片、控制台和浏览器示意图、地图、ADC 梯子、IAM 格子、CORS 流程图、标签、进度条、课件标签和思考题卡片都保持英文，只翻译旁白。

## 总原则

用一位中国 MLOps 助教在实验课上带同学一步步操作时的普通话，只在这样的人真的会说英文的地方说英文，写成英文旁白下面的字幕。观众已经会说“把 repo clone 下来”“起一个 container”“构建 image”“发布一个 port”“调 embedding 模型”“建一个 collection”“建一个 bucket”“调一个 endpoint”“装个 hook”；这一讲再加上“建一个服务账号”“下载 JSON 密钥”“走 ADC”“换一个 bearer token”“查 IAM”“报 403”“跨域”“配 CORS”“发预检请求”“看 origin”“走 Docker DNS”。每个选择过三关：实验课上的真实说法；能搜到的标准中文名（Google Cloud 中文文档：服务账号、应用默认凭据、访问令牌、元数据服务器、身份联合、最小权限；MDN 中文文档：跨域、同源、预检请求、请求头；网络教材：回环地址、幂等）；和系列保持一致（第 1 讲定下共用的词，第 2–4 讲定下容器、密钥和网络的词，第 5 讲定下 RAG 的词，第 8 讲定下 endpoint，第 9 讲定下最后几条约定：它们定下的写法一律沿用）。

1. **实物原样**：观众要输入、要在屏幕上对照的东西（命令、参数、文件名和目录名、路径、image / container / 网络 / collection 的名字、地址和 port、服务账号名、角色名、控制台标签、错误信息和终端原文、HTTP 状态码、请求头名字、README 标题、画面上的标签）逐字照抄，不翻译、不变形、不加引号。检查器逼出来的例外（实物里有下划线、=、< >、+ 或括号）按旁白的说法写（A6），英文行显示原样（D4）。终端输出、代码面板、README 卡片、控制台和浏览器示意图、IAM 格子、地图、标签、进度条、课件标签和思考题卡片都是英文，只翻译旁白。
2. **实验课口语里的英文，封闭清单**：第 1–9 讲的 repo、clone、commit、pin、root、shell、container、image、Dockerfile、tag、pull、port、host port、container port、localhost、bind mount、bucket、API、ID、bug、chunk、embedding、collection、agent、LLM、endpoint、hook；**这一讲新增 IAM（系列里本来就说“IAM 角色”）、ADC（第一次出现时带上“应用默认凭据”）、OAuth、API key、bearer token、JSON Web Token、CORS、origin、Docker DNS、Wi-Fi**。

## 关键决定

- **和 BRIEF 提示不同的地方：系列一致性优先**（A1、A3）。BRIEF 的 “Chinese glossary heads-up”（BRIEF.md:678–681）建议 service account、key、token、bearer token、ADC、IAM、principal、role、CORS、preflight、origin、bind mount、mount、port、localhost、Docker DNS、endpoint、embedding、bucket、prefix 都保留英文。其中第 3–5 讲已经定成中文的，这里沿用：**服务账号、密钥、访问令牌 / 令牌、角色、挂载、前缀**（第 3 讲明确写过“字幕里不说 token”指访问令牌）；preflight 用 MDN 的标准译名**预检请求**；principal 在旁白里没有出现（只在简介里，写“身份”）。其余照 BRIEF：**bearer token、ADC、IAM、CORS、origin、bind mount、port、localhost、Docker DNS、endpoint、embedding、bucket** 保留英文。这几处是待 Conny 确认的决定。
- **身份验证 ≠ 授权**（A3、A7，同第 3 讲）：authentication → 身份验证，authorization → 授权；绝不只写“认证”（会把两者混在一起）；grant → 授予；OAuth 的 consent screen → 授权同意页面。401 是“没有有效的令牌”，403 是“身份验证通过了，但授权失败了”。
- **令牌的几种说法分清楚**（A7）：access token → 访问令牌，单说 the token → 令牌；英文说 bearer 的地方才写 bearer token（Authorization 请求头里的写法，中文的“不记名令牌”没人说）；JSON web token → JSON Web Token；the ticket → 票（一小时有效的票）。
- **origin 保留英文，跨域和同源说中文**（A13）：单独的“源”容易和数据源、源代码混；页面的 origin、指定的 origin；crosses origins → 跨域；Origin 请求头照写。guest list → 白名单（publish.description_zh 也写“CORS 白名单”），pass → 通行证，bouncer → 保安。
- **Docker DNS 照说**（A13）：英文旁白直接说出了 Docker DNS（第 4 讲的英文没说，所以那里只说“电话簿”）；a phone book on each street → 每条街上的一本电话簿。
- **进度条的六个阶段、README 的节、视频的两部分、第 n 步分开**（A7）：进度条的 stage → 阶段（左上角的进度条按六个阶段跟着 README 走）；README 的 section → 节；视频的 part → 第一部分 / 第二部分；README 和应用里的 Step → 第 n 步（Step 1 of 5 → 5 步里的第 1 步）。
- **授课老师的名字不写**（A10）：the instructor's endpoint → 授课老师的 endpoint；README 第五个界面步骤的标题带着授课老师的名字，字幕从不写它，照旁白说“第 5 步是微调过的奶酪模型”。
- **带下划线的名字**（A6、B3）：GCP_PROJECT → GCP project 这个变量（同第 5 讲）；GOOGLE_APPLICATION_CREDENTIALS → Google application credentials 这个变量（这一讲的旁白直接念出了它的名字）；uvicorn_server → uvicorn server；x86_64 → x86（照旁白）。英文行用 en_display 给出字面形式（D4）。
- **疏漏一律说“一个小疏漏”**（A9，同第 5、9 讲）：S02 托管部署的文件被删了，S06 书名在第一个点处被截断，S08 没有哪个 README 说要启用 Vertex AI API，S10 前端配置里的 docs 路径；S09 的第 14 行是“这个 repo 里最大的疏漏，不是你的错”。.gitignore 那条是“陷阱”（英文就叫 trap）。
- **S05 的如实说明**（A9）：这台机器没有 Google 账号，目录列表里的密钥是一个明显无效的替身，云端步骤之前就删掉了；之后每个成功结果都标着 recorded 并注明出处。说得和英文一样平实，不道歉，也不藏。
- **画面标签照画面写**（同第 2–9 讲）：黄色的 your turn 标签、灰色的 extra 标签、标着 recorded；GOLD 计费标签按颜色说“金色标签”。旁白自己说的照常翻译：额外检查、进度条、地图、格子、保安（A11）。
- **录制时**：at the time of recording 每次都译“录制时”，绝不省略（8248 和 14228 个 chunk、1.0.0、170 个包大约三分钟、773 个包、14.2.4）（A9）。
- **按英文时间轴读**：中文是边听英文边读的，每句中文读起来的时间要和英文听起来差不多；删掉多余的连接词和重复的主语，绝不删内容；长实物（Gemini Enterprise Agent Platform User、llm-service-account.json、localhost:3200/finetunechat）英文没重复的地方不要重复（D8）。

### G. 字幕

- **[G1]** 宽度。双语字幕带：中文一行最多 30 个单位，英文一行 96 个字符；纯中文字幕（.zh.srt）每行 22 个单位，每条两行。分句写到最多大约 24 个单位，用 ，；： 隔开，让切分器有干净的切点；避免超过 30 个单位却没有标点的分句。长角色名单独成一个分句（……两个角色：Storage Admin，和 Gemini Enterprise Agent Platform User。）。
- **[G2]** 字幕条的结尾：工具链会去掉条末的 。，、；：，保留 ？！…… 和收尾的 ”（subtitles.strip_end）。能用中文词收尾的，就不要以实物加句号结束（……放在 secrets 目录里。比 ……secrets。好读）。
- **[G3]** 命令不拆行。切分器把中文行里两个拉丁词之间的空格当作好切点，所以 docker compose down 或 docker network connect 可能被拆到两行，观众就没法照抄了。整条命令放在全角冒号之后、分句末尾（README 的停止命令：docker compose down。；然后输入 exit。），每条字幕最多一条命令，周围少放中文。一行放不下或含 A6 字符的命令，按 SAY 的说法分开描述（README 那条先检查、不存在再创建的网络命令；从 API container 里面按名字问数据库）。在渲染出来的 .zh.srt 里逐条检查带命令的字幕。
